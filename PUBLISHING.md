# Publishing Duzek

The publication coordinates are `io.github.necdetzr:duzek:<version>`.
Release versions are immutable on Maven Central. Keep `version` in
`build.gradle.kts` aligned with the source commit used for the release.

## Publisher setup

The publisher needs a verified `io.github.necdetzr` namespace in Central Portal,
a Central Portal user token, and a local GPG signing key whose public key is
available from a keyserver.

Put publisher settings in your **user-level** Gradle properties file, not the
project's `gradle.properties`. On this Windows machine that file is
`C:/Users/Necde/.gradle/gradle.properties`. Preserve any existing settings.

```properties
# The username and password generated by Central Portal's user-token feature.
mavenCentralUsername=REPLACE_WITH_TOKEN_USERNAME
mavenCentralPassword=REPLACE_WITH_TOKEN_PASSWORD
signAllPublications=true

# Use forward slashes for Windows paths in .properties files.
signing.gnupg.executable=C:/Program Files/GnuPG/bin/gpg.exe
signing.gnupg.keyName=REPLACE_WITH_FULL_FINGERPRINT
```

Use your actual GPG installation path if it differs. GPG's agent manages the
private key and requests its passphrase through a local prompt when needed.
There is no need to export the private key or store its passphrase in the repo.
Never commit the user properties file or share its contents in an issue.

## Build and local verification

Run from the project root in PowerShell:

```powershell
.\gradlew.bat build
.\gradlew.bat publishToMavenLocal
```

The publication includes a library JAR, sources JAR, Dokka documentation JAR,
POM, module metadata, and signatures. Tests and ordinary builds do not need
Central credentials.

For a local packaging check without access to a signing key, disable signing
explicitly (the plugin only registers signatures when signing is enabled):

```powershell
.\gradlew.bat publishToMavenLocal -PsignAllPublications=false
```

Signing must be enabled for a Central upload. This property lets contributors
run local packaging checks without needing the publisher's key.

In a separate Kotlin/JVM consumer project, temporarily use:

```kotlin
repositories {
    mavenLocal()
    mavenCentral()
}

dependencies {
    implementation("io.github.necdetzr:duzek:0.1.0")
}
```

Verify both basic calls and explicit pronunciation. Remove `mavenLocal()` when
verifying the publicly released package so a local copy cannot mask a missing
Central release.

## Upload and release

After tests, local consumption, and signing checks pass, upload with:

```powershell
.\gradlew.bat publishToMavenCentral
```

Automatic release is disabled. Review validation under
[Central Portal Deployments](https://central.sonatype.com/publishing/deployments),
then click **Publish** for the validated deployment. A successful local build
or upload does not mean the package has been publicly released.

After publication, verify the dependency in a consumer using only
`mavenCentral()`, update the README installation section, and publish a matching
GitHub release. Commit and push the release configuration yourself.
